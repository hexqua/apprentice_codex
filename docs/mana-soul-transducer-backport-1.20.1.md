# マナソウルトランスデューサーの1.20.1実装と仕様差

## 移植元と共通資産

たたき台は `cc859399d2d345f4d82ea405e196f84452cc5520`。この文書を追加する1.21.1の変更は、Malum 1.8.2の属性連携とSoulConversionを実装する。1.20.1 / Malum 1.6.7は杖の回数管理が異なるため、機能をそのままcherry-pickして完了とはしない。1.20.1側では以下の仕様で再実装した。

- アイテム名「マナソウルトランスデューサー」、ID `apprenticecodex:mana_soul_transducer`、画像・アニメーション・モデルは維持する。
- `ja_jp`・`en_us`・`zh_cn`の翻訳を流用し、アイテム説明は `legacy.desc_1～3` に切り替える。`legacy.desc_1` の引数には設定した消費マナを渡す。
- CuriosのcharmとMalumの非表示タグは1.20.1の`tags/items`へ配置する。Soulwoven pouch効率化は1.6.7に対応機能がないため対象外。
- 共通の短縮率計算は移植候補。Malum属性・Attachment・NeoForgeイベントは版固有で置き換える。

## 1.21.1の仕様

装備中、Iron'sの実効LONG短縮率の80%をMalumの `CHARGE_DURATION` へ `ADD_MULTIPLIED_TOTAL` で適用する。クールダウン短縮属性の正の増加分の80%を `CHARGE_RECOVERY_RATE` へ `ADD_MULTIPLIED_BASE` で加算する。2つの反映率はSERVER設定で0～1に調整でき、初期値は0.8。Iron's属性が1未満でもペナルティは転送しない。複数装備は重複しない。

SoulConversionは装備から提供するLONG魔法。基本500マナ・1.5秒・30秒クールダウンで、Iron'sの標準補正を受ける。杖を持たずに使用でき、共有の消費済み量と回復タイマーを0へ戻す。詠唱中に自然回復で満タンになる、または装備を失う場合は無消費で中断する。Malum未導入では強制無効とし、有効魔法一覧を使うEldritch研究画面にも出さない。

## 1.20.1の実装仕様

1.20.1ではアイテムクールダウンと共有予備回数が別管理であり、1.21.1の回復速度属性連携は移植しない。予備回数の上限や600進捗での自然補充も変更しない。

### マナ優先の発射

- 完全チャージして実際に発射が成立する際、まず80マナを支払おうとする。
- 支払えれば、今回の発射による予備回数消費とアイテムクールダウン発生を回避する。耐久消費など他のMalum処理は維持する。
- 支払えなければ、Malum本来の「予備回数消費、なければクールダウン」へ戻る。
- 使用開始時には支払わない。途中キャンセル、チャージ不足、発射不成立では消費しない。

### 既存クールダウンの解除

- 装備中にクールダウン中のMalum杖を持った場合、80マナを支払えるなら消費して、その種類の杖のクールダウンを解除する。
- 解除の支払いと、次の発射時の支払いは独立する。解除直後の発射でも追加80マナを使い、支払い済みフラグは保持しない。
- マナが不足していれば既存クールダウンを維持する。解除済みの杖から毎tickマナを取り続けない。
- サーバーでのみ支払いを確定し、マナとアイテムクールダウンをクライアントへ同期する。

### 発動チャージ短縮

Iron'sの詠唱短縮属性を `C`、反映率を `k` として、基本tick数に以下の時間倍率を掛ける。`k` の初期値は0.8、設定範囲は0～1とする。

```text
1 − k × max(0, softCapFormula(max(1, C)) − 1)
```

Malum 1.6.7の `AbstractStaffItem` へMixinで介入する。Itemの共有フィールドを書き換えず、使用者ごとの計算へ置き換える。releaseUsingの発射判定、onUseTickの演出・完了音を同じ時間へそろえ、端数tickと最短時間を検証する。通常のクールダウン使用制限についても、解除の同期と整合させる。

### SoulConversionの省略

1.20.1ではMalumの有無にかかわらずSoulConversionを常時無効とする。IDと資産を残しても、`config.enabled=false` に加えて実効 `isEnabled()` をfalseにし、設定上書きでも有効化させない。魔法選択への提供と発動処理を移植せず、Eldritch研究画面にも出さない。

## 移植時の検証

- `.codex/skills/backport-1-20-1` に従い、共通資産と版固有コードを区別して取り込む。
- Java 17で `build` と通常・Malum連携GameTestを実行する。失敗時は `report-gametest-failure` に従う。
- マナ十分・不足、予備回数あり・なし、既存クールダウン、解除と次発射の二重の支払い、未装備、複数装備、途中キャンセルを確認する。
- 発動チャージ短縮の反映率0・0.8・1、Iron's属性1未満・通常域・ソフトキャップ域、演出と発射タイミングを確認する。
- Malumなしでも専用サーバーが起動し、SoulConversionが常に無効であることを確認する。
- リソース再生成時には旧パスのstale出力を除去し、実行条件・タグ形式・翻訳の引数をtarget側へ合わせる。

## 実装上の補正

- 設定は`Items.ManaSoulTransducer.castTimeReductionTransferRate`（既定0.8、0～1）と`manaCost`（既定80、0～1000000）。回復速度転送設定は1.20.1には設けない。
- チャージ時間は切り上げ・最低1 tick。同一Itemの共有フィールドを変更せず、発射・演出・完了音の参照を使用者ごとに補正する。
- 発射後の予備回数取得だけを呼出しローカルの代替capabilityへ切り替え、本物の予備回数・回復進捗を保存したまま消費を回避する。代替capabilityはプレイヤーに保存しない。
- 既存クールダウンはサーバーtickで両手を確認して種類ごとに解除する。同じ種類を両手に持っても二重払いは発生しない。
- クリエイティブでの発射はMalum本来の無消費処理を維持する。
- レシピはForge条件とMalum 1.6.7の`extra_items`・`output`形式でdatagenする。
- 既存杖のエンチャント適用と修理素材は変更しない。
- クライアントの画面・演出は手動確認対象。自動検証では専用サーバーの起動・ゲームロジックを確認する。
