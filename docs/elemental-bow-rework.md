# Elemental Bow リワークのリリース準備

既存の弓はそのまま使用できる。名前・耐久値・エンチャントは維持し、旧仕様の自動生成された固定魔法だけを除去する。
初回のインベントリ更新・使用・術式調整台への設置時に移行する。
旧魔法選択は通常射撃へ戻り、魔法を使うにはスクロールの装着が必要になる。新形式の装着済みスクロールは再移行で削除しない。

このドキュメントは次バージョンリリース時にCurseForge/Modrinthのchangelogに破壊的変更点やリワーク内容を要約して削除する。

## 新仕様

- 術式調整台でスクロールを装着する。秘術の鉄床による Imbue は引き続き不可。
- 調整スロット3、スクロールスロット初期1。lesser_spell_slot_upgrade で1枠ずつ、最大4枠へ拡張する。
- 同じ魔法を複数枠へ装着できる。拡張を取り外して無効になった枠の現物は保持し、調整台から取り出せる。
- 魔法レベルはスクロールのレベル + Transcendence（魔法の上限まで）。Power・Flame は魔法レベルに影響しなくなる。
- オーバーヒートシステムはプレイヤー単位で全弓・全魔法が共有する。物理射撃は過熱を増やさない。
- 冷却は WeaponImbue の武器倍率を除く魔法クールダウンを基準とし、既存の冷却期限を短い魔法で短縮しない。通常詠唱のクールダウンを生成・上書きしない。
- 過熱はログアウト・サーバー再起動をまたいで保持し、死亡時はリセットする。リワーク前仕様 school 別オーバーヒートデータはログイン時に除去する。
- 魔法射撃の矢消費は従来どおり。Infinity は適用せず、Synthesis で不要になる。詠唱銃のツールチップをある程度流用するが詳細ツールチップには弾の項目を表示しない。
- school の表示アイコンはそのまま使用する。同じ school の複数魔法に同じアイコンが出ることを許容する。
- Schoolルーンと回復のルーンはそれぞれ1個まで、既存の調整スロットへ装着できる。併用時はスロット拡張が1個までとなり、使用可能なスクロールは最大2枠になる。
- Schoolルーンは魔法のスペルパワーの参照系統を変更する。元の系統が一致していても、通常分とオーバーヒート追加分の両方のマナ消費に倍率を掛ける。サーバー設定 `Items.ElementalBow.schoolRuneManaCostMultiplier` は既定2倍、1〜10倍。魔法ID・ダメージ種別・習得条件・選択アイコンの系統は変更しない。
- 回復のルーンはオーバーヒートをプレイヤーのスクロール番号別にする。同じ番号は別の弓でも共有する。回復のルーンがない弓は、空・無効枠を含む全4枠の最大連鎖数と最長期限を参照し、成功時に全枠を最大連鎖数+1と共通の期限へ揃える。ルーンやスクロールの着脱ではオーバーヒートを消さない。
- 第1段階の単一オーバーヒートデータは同じ保存ルート内の `Slot0`〜`Slot3` へ複製して移行する。保存・同期は引き続きプレイヤー単位で、死亡時は全枠をリセットする。
- 魔法詳細はSchoolルーンの補正と通常マナ倍率を反映し、一時的なオーバーヒートマナは反映しない。能力欄の2倍は200%、JEIの増加量は+100%と表示する。

## データパック・設定の破壊的変更

更新時は Elemental Bow を変更するデータパックを見直すこと。

対象は従来と同じ `data/<namespace>/elemental_bow_modes/*.json`。
外側の `values` 配列と各要素の `spell`、`required_draw_ticks`（省略時20）は維持する。`school` と `enchantment_bonuses` は廃止し、school は魔法自身の設定から取得する。
旧フィールドが残っていても読み込み時には使わない。
school 重複の排除は行わない。
詠唱形式は LONG と INSTANT に対応する。INSTANT も弓を放した処理内で発動を完了し、Schoolルーンと通常クールダウン除外を適用する。
CONTINUOUS は引き絞りと両立しないため、サーバーのデータ読込時に定義元と魔法IDを警告して登録を拒否する。
別ファイルで同じ spell が定義された場合はリソースID順で後の定義を採用する。
旧仕様への互換変換は提供しない。

`Items.ElementalBow.powerArrowSpellLevelBonusPerLevel` は廃止する。
他の矢・引き絞り・オーバーヒート設定は維持する。

## 移植時の境界

スクロール現物保持、スロット数、レベル計算、共有過熱、定義形式は共通ロジック。
1.20.1 では ItemStack の DataComponents を NBT へ、registry lookup とパケット登録を Forge API へ補正する。
通常CDを回避する Mixin は Iron's 3.x の該当メソッドを確認する。
generated/resource は移植先で runData し、旧フィールドの削除差分も確認する。
